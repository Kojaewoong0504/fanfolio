# Fanfolio 카드 재질·홀로그램·뒷면 효과 설계

## 목적

아티스트가 실물 포토카드에서 익숙한 포일, 펄, 스팟 UV, 인증 씰을 사용하면서 디지털 카드에서만 가능한 기울임 반사와 렌티큘러 전환을 더할 수 있게 한다. 편집 결과는 아티스트 스튜디오와 팬 앱 카드 상세에서 같은 설정과 같은 시각 규칙으로 재생되어야 한다.

이번 변경은 현재 정적 ES 모듈 구조와 기존 `designConfig` 계약을 유지한다. WebGL 렌더러나 새 프레임워크를 도입하지 않고 CSS 마스크, 합성 레이어, 포인터·터치 입력을 조합하는 하이브리드 방식으로 구현한다.

## 승인된 방향

기본 카드는 절제된 실물 포일처럼 보이게 하고, 희귀 카드에서만 렌티큘러와 모션 효과를 강하게 사용한다.

- 일반 카드: 무광·펄·크롬 재질과 부분 포일
- 레어 카드: 크랙드 아이스, 프리즘, 스타더스트 패턴
- 스페셜 카드: 두 장의 이미지가 기울기에 따라 전환되는 렌티큘러
- 모든 카드: 움직임 감소 환경에서 정적인 고품질 대체 표현

과도한 자동 회전이나 화면 전체를 덮는 무지개 애니메이션은 사용하지 않는다. 빛은 카드가 움직이는 방향에 반응하고, 카드 자체는 사용자가 직접 움직일 때만 기울어진다.

## 범위

### 포함

- 스티커 선택 카드의 이미지와 전체 이름이 항상 보이는 UI
- 앞면 표면 재질, 포일 패턴, 적용 범위, 상호작용의 독립 설정
- 두 번째 이미지를 사용하는 렌티큘러 미리보기
- 뒷면 전용 표면 재질, 금·은 포일, 스팟 UV, 인증 씰, 숨은 메시지
- 포인터·터치 기반 기울임과 모바일 기기 방향 센서 선택 사용
- 움직임 감소와 센서 거부 상황의 정적 대체 표현
- 기존 `effectPreset`과 `effectFinish` 데이터의 하위 호환
- 아티스트 스튜디오와 팬 앱의 동일 효과 계약 소비

### 제외

- 실시간 3D 모델, WebGL 셰이더 편집기
- 자동 인물 분할이나 AI 마스크 생성
- 세 장 이상의 렌티큘러 프레임
- 영상 편집 타임라인과 키프레임 애니메이션
- 인쇄용 CMYK·박·UV 제작 파일 출력

인물 뒤에만 포일을 넣는 정밀 효과는 별도의 마스크 자산이 필요하다. 이번 범위에서는 전체, 프레임, 중앙 배경, 로고·사인 영역처럼 카드 레이아웃으로 확정 가능한 마스크만 제공한다.

## 효과 모델

앞면 효과는 `재질 × 패턴 × 적용 범위 × 상호작용`의 네 축으로 구성한다. 각 축은 독립적으로 바꿀 수 있어 프리셋 수가 늘어나도 렌더링 규칙이 중복되지 않는다.

### 재질

- `matte`: 반사가 거의 없는 무광 코팅
- `pearl`: 낮은 강도의 미세한 진주광
- `chrome`: 선명한 금속성 반사

### 포일 패턴

- `aurora-wave`: 부드러운 오로라 곡선
- `prism`: 각도에 따라 분리되는 무지개 분광
- `cracked-ice`: 실물 스포츠 카드에서 보이는 조각형 포일
- `micro-star`: 작은 별 입자가 드러나는 스타더스트

### 적용 범위

- `full`: 카드 전체
- `background`: 중앙 배경 영역
- `frame`: 가장자리 프레임
- `signature`: 하단 로고·사인 영역

### 상호작용

- `static`: 선택한 각도의 정적 반사
- `tilt`: 포인터, 터치 또는 허용된 기기 방향에 따라 빛 이동
- `lenticular`: 수평 기울기에 따라 기본 이미지와 보조 이미지 전환

렌티큘러를 선택했지만 보조 이미지 자산이 없으면 미리보기는 기본 이미지를 유지하고 속성 패널에 보조 이미지 추가 안내를 표시한다. 검수 요청 단계에서는 누락으로 처리한다.

## 스티커 선택 UX

현재 두 열 가로 배치는 좁은 속성 패널에서 이름을 한두 글자로 줄인다. 이를 이미지 중심의 정사각형 타일로 바꾼다.

- 타일 상단에 64px 이상의 스티커 미리보기
- 하단에 최대 두 줄의 전체 한글 이름
- 별도의 `+` 아이콘 없이 타일 전체가 추가 버튼
- 추가 후 짧은 선택 피드백과 카드 위 레이어 자동 선택
- 키보드 포커스와 `aria-label`에 전체 이름 제공
- 모바일 속성 시트에서는 두 열, 매우 좁은 화면에서는 한 열

업로드 영역은 기본 스티커 아래에 유지한다. 기본 제공과 직접 업로드가 서로 대체 관계처럼 보이지 않게 구분 제목을 사용한다.

## 앞면 편집 UI

기존 ‘홀로그램’ 도구 이름은 유지하되 속성 패널을 네 구역으로 재구성한다.

1. 표면 재질: 무광, 펄, 크롬
2. 포일 패턴: 오로라 웨이브, 프리즘, 크랙드 아이스, 마이크로 스타
3. 적용 범위: 전체, 배경, 프레임, 로고·사인
4. 반응 방식: 정적, 기울임, 렌티큘러

하단에는 광택 강도와 빛 각도를 둔다. 선택한 옵션은 작은 텍스처 썸네일과 짧은 설명으로 구분한다. 렌티큘러를 선택하면 보조 이미지 업로드 또는 기존 사진 선택 영역이 나타난다.

프리셋은 사용자의 빠른 시작을 위해 유지하되 내부적으로 네 축의 조합을 적용한다.

- 소프트 펄: `pearl + aurora-wave + full + tilt`
- 프리즘 프레임: `chrome + prism + frame + tilt`
- 크랙드 아이스: `chrome + cracked-ice + full + tilt`
- 사인 스포트라이트: `pearl + micro-star + signature + tilt`
- 렌티큘러 스페셜: `pearl + aurora-wave + background + lenticular`

## 뒷면 편집 UI

뒷면은 단순 색상 변경이 아니라 공식 카드의 신뢰성과 소장 가치를 표현하는 면으로 설계한다.

### 표면

- 무광, 펄, 크롬 중 하나
- 기존 공식 뒷면 템플릿과 바탕색 위에 합성

### 테두리 포일

- 없음, 실버, 골드
- 테두리와 코너 장식에만 적용

### 스팟 UV

- 없음, 로고, 중앙 심볼, 시리얼 영역
- 선택 영역만 각도에 따라 짧게 반사

### 인증 요소

- 발행 번호가 있으면 `No. 0042 / 5000` 형식으로 표시
- 공식 인증 씰은 서버에서 제공하는 카드 ID의 짧은 식별값을 표시
- 씰은 장식이 아니라 팬이 공식 카드 여부를 확인하는 정보로 사용

### 숨은 메시지

- 아티스트가 짧은 문구를 입력
- 정면에서는 낮은 대비로 보이고 기울였을 때 선명해짐
- 최대 40자, 줄바꿈 2줄 제한

뒷면 색상은 템플릿 이미지와 독립된 오버레이로 적용한다. 이미지의 명도 정보를 유지하고 선택 색상을 실제 렌더링 변수로 반영한다.

## 렌더링 구조

카드 렌더러는 다음 순서로 합성한다.

1. 기본 이미지 또는 뒷면 템플릿
2. 렌티큘러 보조 이미지
3. 표면 재질 레이어
4. 적용 범위 마스크를 가진 포일 패턴
5. 창작 레이어: 손글씨, 그림, 스티커
6. 카드 제목과 공식 표기
7. 뒷면 인증 씰, 시리얼, 숨은 메시지

포일 레이어는 카드 위치를 기준으로 고정하고 `--light-x`, `--light-y`, `--tilt-x`, `--tilt-y` CSS 변수만 갱신한다. 텍스처 자체를 반복 이동시키지 않아 미끄러지는 배경처럼 보이는 문제를 피한다.

스튜디오와 팬 앱은 동일한 클래스 이름과 CSS 변수 의미를 사용한다. 공통 설정 정규화 함수는 `studio-core.js`에서 관리하고, 팬 앱은 API의 `designConfig`를 읽어 같은 데이터 속성과 클래스를 만든다.

## 데이터 계약

`designConfig.version`은 `3`으로 올리며 기존 필드는 읽을 수 있게 유지한다.

```json
{
  "version": 3,
  "front": {
    "material": "pearl",
    "foilPattern": "aurora-wave",
    "foilCoverage": "frame",
    "interaction": "tilt",
    "intensity": 0.58,
    "angle": 135,
    "lenticularAssetId": null
  },
  "back": {
    "templateId": "official-violet",
    "background": "#6f61c9",
    "material": "matte",
    "edgeFoil": "silver",
    "spotUv": "logo",
    "hiddenMessage": "우리의 다음 계절도 함께해요"
  }
}
```

### 하위 호환

- `effectFinish=glass`는 `material=pearl`
- `effectFinish=silk`는 `material=matte`
- `effectFinish=diamond`는 `material=chrome`
- 기존 `effectPreset`은 가장 가까운 `foilPattern`으로 변환
- 기존 `effectMotion=false`는 `interaction=static`
- 기존 `effectMotion=true`는 `interaction=tilt`

저장 시 새 필드를 우선 사용한다. 이전 필드는 서버와 구버전 클라이언트 호환을 위해 한 번의 마이그레이션 기간 동안 함께 보존한다.

## 입력과 접근성

### 데스크톱과 태블릿

- 포인터 이동으로 카드 기울기와 빛 위치를 갱신
- 포인터가 카드를 벗어나면 부드럽게 정면으로 복귀
- 터치 드래그는 카드 회전보다 페이지 스크롤을 우선하며, 카드 위에서 명시적으로 드래그할 때만 효과 적용

### 모바일 기기 방향

- 기본값은 꺼짐
- 사용자가 ‘기기 움직임으로 보기’를 누른 뒤에만 센서 권한 요청
- 권한 거부 또는 미지원 시 터치 기반 기울임 유지
- HTTPS 환경에서만 센서 기능 노출

### 움직임 감소

- `prefers-reduced-motion: reduce`에서는 자동 복귀 애니메이션과 반복 광택을 중단
- 현재 각도에서 정적인 포일 이미지를 표시
- 렌티큘러는 명시적 앞·뒤 이미지 전환 버튼을 제공

## 오류와 복구

- 보조 이미지 업로드 실패: 기존 이미지와 효과 설정을 유지하고 다시 시도 제공
- 센서 권한 거부: 오류 문구 대신 터치로 볼 수 있다는 안내 표시
- 저성능 환경: 합성 레이어 수를 줄인 정적 포일로 자동 대체
- 알 수 없는 효과 값: `matte + aurora-wave + full + static`으로 안전하게 정규화
- 구버전 카드: 하위 호환 매핑 후 렌더링하고 사용자가 저장할 때 버전 3으로 갱신
- 뒷면 메시지 초과: 40자에서 저장을 막고 남은 글자 수 표시

## 테스트 전략

### 단위 테스트

- 버전 2 효과 설정이 버전 3 값으로 정확히 정규화되는지 검증
- 허용되지 않은 재질·패턴·범위·상호작용 값의 안전한 기본값 검증
- 렌티큘러 선택 시 보조 이미지 누락을 검수 실패로 계산
- 뒷면 메시지 길이와 시리얼 표시 형식 검증
- 앞면과 뒷면 효과 값이 서로 덮어쓰지 않는지 검증

### UI 회귀 테스트

- 스티커 타일이 전체 이름을 표시하고 말줄임을 사용하지 않는지 검증
- 효과 패널에 네 축과 뒷면 옵션이 노출되는지 검증
- 카드 렌더러가 재질·패턴·범위 클래스를 함께 출력하는지 검증
- 뒷면에 색상, 포일, 스팟 UV, 인증 요소가 렌더링되는지 검증
- 센서 권한이 사용자 버튼 동작 뒤에만 요청되는지 검증
- 움직임 감소 CSS가 반복 모션을 끄는지 검증

### 통합 확인

- 스튜디오에서 만든 버전 3 초안을 저장하고 다시 열어 동일하게 복원
- 팬 앱 카드 상세에서 같은 앞면·뒷면 효과 확인
- 데스크톱 포인터, 태블릿 터치, 모바일 센서 거부·허용 흐름 확인
- 구버전 공개 카드가 시각적으로 깨지지 않는지 확인

## 구현 경계와 완료 조건

이번 작업은 효과 계약 정규화, 스튜디오 편집·미리보기, 팬 앱 상세 렌더링, 테스트까지 한 계획으로 구현한다. 백엔드가 `designConfig`를 불투명 JSON으로 저장하므로 데이터베이스 스키마 변경은 요구하지 않는다. 보조 이미지 자산은 기존 업로드 API를 재사용한다.

완료 조건은 다음과 같다.

1. 스티커 네 종류의 이미지와 전체 이름을 선택 전에 식별할 수 있다.
2. 앞면에서 재질, 패턴, 범위, 반응 방식을 독립적으로 바꿀 수 있다.
3. 보조 이미지가 있는 렌티큘러 카드가 수평 기울기에 따라 자연스럽게 전환된다.
4. 뒷면의 색상, 표면, 테두리 포일, 스팟 UV, 인증 요소와 숨은 메시지가 실제 카드에 반영된다.
5. 센서 권한을 강요하지 않고 포인터·터치·정적 대체 방식이 모두 작동한다.
6. 저장 후 재접속과 팬 앱 상세에서 같은 효과가 유지된다.
7. 기존 카드와 기존 테스트가 깨지지 않으며 새 회귀 테스트가 통과한다.
