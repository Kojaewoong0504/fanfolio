# Fanfolio 관리자 운영 웹 전면 개편 설계

## 1. 목표

참고 이미지의 깨끗한 데스크톱 운영 도구 경험을 Fanfolio 관리자 웹 전체에 적용한다. 화면은 업무 단위로 정리하고, 루트 관리자와 기업 관리자가 같은 디자인 시스템을 쓰되 접근 범위와 권한은 엄격히 분리한다.

기준 화면은 `전역 내비게이션 + 파트너 디렉터리 + 상세 작업 영역`의 3단 구조다. 이 구조는 파트너 관리에 적용하고, 나머지 운영 화면은 전역 내비게이션과 넓은 작업 영역의 2단 구조를 사용한다.

## 2. 사용자와 권한 모델

### 루트 관리자

- Fanfolio 플랫폼 운영 책임자다.
- 파트너 회사 생성·계약·중지·로고, 회사 관리자 발급·비활성화·권한 변경, 회사 아티스트 연결을 관리한다.
- 전체 아티스트, 카드, 드롭, 코드, 서비스 사용자, 감사 로그에 접근한다.
- 카드와 드롭의 최종 공개, 드롭 중지, 코드 무효화, 재고 조정은 루트 관리자만 실행한다.

### 기업 슈퍼 관리자

- 정확히 하나의 파트너 회사에 소속된다.
- 자기 회사의 관리자 초대·비활성화·역할 변경, 회사 아티스트 연결, 담당자별 아티스트 배정을 관리한다.
- 자기 회사와 연결된 아티스트의 카드·드롭·코드·감사 로그에 접근한다.
- 플랫폼 계약, 다른 회사 데이터, 전체 서비스 사용자에는 접근하지 못한다.

### 매니저

- 배정된 아티스트의 카드·드롭·코드 초안을 생성·수정한다.
- 검수·발행 요청을 제출할 수 있으나 최종 공개·중지·무효화는 할 수 없다.

### 에디터

- 배정된 아티스트의 카드와 드롭 콘텐츠 초안을 편집한다.
- 코드 배치 생성, 발행 요청, 관리자·배정 변경은 할 수 없다.

### 뷰어

- 자기 회사 범위의 카드, 드롭, 코드 사용 현황, 감사 로그를 읽기만 한다.

### 범위 판정

각 요청은 `organizationId`, `accessLevel`, `assignedArtistIds`, `allowedActions`를 서버에서 함께 판정한다. 프런트의 메뉴 숨김은 편의 기능일 뿐이며, 범위 밖 리소스는 서버에서 `404`, 허용되지 않은 동작은 `403`으로 거절한다.

## 3. 정보 구조

### 공통 셸

- 좌측 탐색: 개요, 파트너(루트), 아티스트, 카드, 드롭·코드, 감사 로그, 서비스 사용자(루트).
- 상단: 현재 범위 배지(ROOT 또는 회사명), 알림, 계정 메뉴.
- 하단 계정 영역: 현재 사용자, 역할, 로그아웃. 좁은 화면에서는 접히는 메뉴로 전환한다.
- 기존 별도 설정과 가이드 화면은 상단 도움말과 각 업무 화면의 문맥 안내로 흡수한다.

### 파트너 관리 — 루트 전용

- 좌측: 회사 검색, 활성/중지 필터, 로고, 회사명, 상태, 관리자·아티스트 수, 페이지 이동.
- 중앙 상세 헤더: 로고, 회사명, 상태, 계약 상태/기간, 담당자, 발행 카드 수, 최근 업데이트, 정보 수정.
- 상세 탭: 개요, 관리자, 아티스트, 운영 현황.
- 관리자 탭: 관리자 검색, 역할, 담당 아티스트, 최근 로그인, 상태, 더보기 작업, 관리자 추가, 아티스트 배정 popover.
- 파트너 등록·수정은 오른쪽 drawer, 중지·재활성화는 확인 dialog를 사용한다.

### 아티스트

- 루트: 회사 연결, 스튜디오 계정, 프로필 검수 상태를 포함한 전체 아티스트 관리.
- 기업: 자기 회사·배정 범위 아티스트의 프로필, 멤버, 카드 초안 현황.
- 아티스트 스튜디오에서 만든 카드와 운영팀이 만든 카드를 명시적으로 구분한다.

### 카드

- 기본 화면은 검색, 아티스트/상태 필터, 카드 테이블 또는 카드형 목록, 상세 미리보기, 작업 메뉴다.
- 카드 생성·수정은 drawer로 통일한다.
- 기업 역할별로 초안 생성·편집·검수 요청만 노출하고, 루트만 최종 공개·중지·운영 카드 등록을 수행한다.

### 드롭·코드

- 기업 관리자는 자기 회사 및 배정 아티스트 범위에서 드롭을 기획하고 카드 연결, 코드 배치 생성 또는 발행 요청을 수행한다.
- 매니저는 초안 생성·수정·발행 요청, 에디터는 콘텐츠 편집, 뷰어는 조회만 가능하다.
- 루트는 모든 회사의 드롭을 조회하고 최종 발행·중지·재고 조정·코드 무효화를 수행한다.

### 감사 로그와 서비스 사용자

- 감사 로그는 조직 및 아티스트 범위로 필터한다. 루트는 전체, 기업은 자기 회사 기록만 본다.
- 서비스 사용자는 루트 전용이다.

## 4. 공통 컴포넌트와 상호작용

- `AdminShell`: 내비게이션, 상단 바, 역할/범위 배지, 반응형 상태를 관리한다.
- `PartnerDirectory`: 파트너 목록과 선택 상세를 분리한다.
- `ScopedWorkspace`: 아티스트·카드·드롭·감사 로그의 목록, 필터, 테이블, 빈 상태를 공유한다.
- `RoleGate`: `allowedActions`로 작업 버튼을 구성하고, 화면 데이터도 동일 범위로 요청한다.
- `Drawer`: 생성·수정 흐름, `Dialog`: 중지·무효화 등 위험 작업, `Popover`: 아티스트 배정과 행 단위 빠른 작업에만 쓴다.
- 입력, select, 날짜 선택, 상태 배지는 커스텀 컴포넌트로 통일해 브라우저 기본 컨트롤 인상을 제거한다.

## 5. 시각 규칙

- 기준 뷰포트: 1440×1024 데스크톱.
- 색상: 흰 표면, 매우 옅은 회색 배경, 짙은 남색 본문, 보라색 단일 강조, 초록 상태 배지.
- 구분은 여백과 1px 선을 먼저 사용한다. 과도한 그림자·테두리·큰 카드 UI를 피한다.
- 전역 내비게이션 208px, 파트너 디렉터리 280px, 상세 영역 유동 폭.
- 버튼 36~40px, 목록 행 52~64px, 표 본문 14px, 보조 텍스트 12~13px을 기본으로 한다.
- 1024~1279px에서는 아이콘 내비게이션과 240px 파트너 목록, 768~1023px에서는 접히는 메뉴와 상단 회사 선택, 767px 이하는 카드형 행과 전체 화면 sheet를 사용한다.
- 모든 화면에서 페이지 전체 가로 스크롤은 허용하지 않는다. popover와 드롭다운은 필요한 셀/영역에서만 clipping을 해제한다.

## 6. 보안·오류·감사 규칙

- 역할 변경·비활성화 시 대상 계정의 refresh 세션을 폐기한다.
- 401은 한 번의 refresh 회전 후 로그인 화면으로 이동한다.
- 403은 역할에 맞는 다음 행동을 안내하고, 404는 범위 밖 존재 여부가 드러나지 않는 일반 메시지로 처리한다.
- 409는 중복 회사 코드·이메일·잘못된 배정을 구체적으로 설명한다.
- 생성·수정 drawer는 저장 중 중복 제출을 막고, 성공 후 목록과 상세 데이터를 함께 갱신한다.
- 계약, 관리자, 배정, 카드, 드롭·코드 변경은 회사와 아티스트 범위를 함께 가진 감사 로그를 남긴다.

## 7. 테스트와 완료 조건

- 백엔드: 조직 범위, 역할별 읽기/쓰기, 배정 아티스트 제한, 드롭·코드의 회사 범위, 세션 폐기, 감사 로그 계약 테스트.
- 프런트: 역할별 메뉴, 파트너 디렉터리, drawer/dialog/popover, 필터, 권한 안내, 1024/1280/1440px 가로 overflow 회귀 테스트.
- 시각 QA: 참고 이미지와 같은 1440px 상태에서 내비게이션, 파트너 목록, 헤더, 탭, 관리자 테이블을 비교하고 P0/P1/P2 차이를 제거한다.
- 배포: 관리자 Node 테스트, JavaScript 구문 검사, lint, 백엔드 pytest/Ruff를 통과한 뒤 GitHub main에 push하고 Vercel 실서비스에서 루트·기업 역할의 핵심 흐름을 검증한다.

## 8. 제외 범위

- 한 사용자의 여러 회사 동시 소속
- 기업 관리자의 계약·플랫폼 과금 관리
- 자동 이메일 초대 발송
- 세부 필드 단위의 자유 권한 편집기
- 아티스트 스튜디오 자체를 관리자 웹으로 병합
