# 팬앱 전체 플로우 보수 계획

## 목표

목업 값이 실제 앱 데이터와 충돌하거나 사용자가 결제 플로우를 건너뛰는 문제를 제거한다. 기존 모바일 디자인 시스템과 라우팅 구조는 유지한다.

## 작업 순서

1. 상점 잔액을 `/me/points`와 연결하고 로딩·오류·빈 상태를 분리한다.
2. 구매·교환 내역을 주문 API와 포인트 원장 API에서 조합하고 요약 수치를 실제 데이터로 계산한다.
3. 상품 상세의 구매 버튼이 주문 API를 즉시 호출하지 않고 상품 식별자를 가진 결제 화면으로 이동하게 한다.
4. 결제 화면에서 상품 상세와 잔액을 불러오고, 현재 백엔드가 지원하는 포인트 결제만 실제 주문 API로 제출한다.
5. 상점 및 거래·컬렉션의 확인 결과와 남은 범위를 감사 MD에 기록한다.

## 검증 기준

- 상점 앱 모드에서 포인트가 하드코딩된 3,250P가 아니라 API 응답을 표시한다.
- 상품 상세 → `/shop/checkout?productId=...` → 구매 제출 → 완료 화면의 순서가 유지된다.
- 구매·교환 내역이 빈 계정에서 목업 행을 표시하지 않는다.
- 기존 프리뷰 경로와 모바일 쉘 레이아웃은 유지된다.
- 상점 관련 회귀 테스트, 전체 테스트, 린트, 빌드를 통과한다.
