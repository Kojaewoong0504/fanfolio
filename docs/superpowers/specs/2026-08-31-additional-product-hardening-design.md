# 추가 고도화 기능 설계

## 목표

팬이 카드의 소유권·획득 근거를 확인하고, 알림에서 실제 작업 화면으로 이동할 수 있게 한다. 이미 존재하는 서버 원장과 알림 엔티티를 재사용하며 NFT나 별도 지갑을 도입하지 않는다. 동시에 현재 통과한 성능 예산을 CI에서 회귀 방지한다.

## 범위

1. 카드 상세의 소유권 이력에 획득 경로와 원장 출처를 사람이 읽을 수 있게 표시한다.
2. 팬 알림 API 타입에 엔티티 목적지를 포함하고, 알림 종류가 아니라 `entityType/entityId`를 우선해 실제 화면으로 연결한다.
3. 프론트엔드 성능 예산 검사를 CI에 추가한다.
4. 아티스트 퍼널 분석은 기존 통계 API의 실제 집계 구조를 확인한 뒤 별도 변경으로 분리한다. 현재 통계 화면에는 서비스 발급 퍼널과 아티스트 활동 지표가 있으므로, 이번 변경에서 더미 퍼널을 새로 추가하지 않는다.

## 비목표

- NFT, 블록체인, 사용자 지갑 또는 외부 서명 시스템 도입
- 기존 원장의 의미를 바꾸는 마이그레이션
- Vercel 배포 또는 외부 운영 데이터 변경

## 설계

### 소유권 이력

기존 `/me/cards/{userCardId}/history` 응답의 `action`, `sourceType`, `sourceId`, `metadata`, 시각을 유지한다. UI는 action과 sourceType을 한국어로 매핑하고, 원장 이벤트마다 “발급·등록·소유권 이동·조합 사용”과 출처를 함께 보여준다. 원장에 없는 정보는 추정하지 않고 “확인 불가”로 표시한다.

### 알림 목적지

`entityType/entityId`가 있는 경우 해당 엔티티 기반 목적지를 우선한다. 지원하는 목적지는 카드·카드팩/드롭·이벤트·시즌 패스/티어·보상·거래·팬 프로필이며, 현재 라우팅할 수 없는 엔티티는 알림을 읽음 처리하고 알림함에 남긴다. 기존 kind 기반 라우팅은 하위 호환용 fallback으로 유지한다.

### 성능 게이트

이미 존재하는 `frontend`의 `perf:budget` 명령을 CI frontend job 뒤에 실행한다. 빌드 결과의 entry JS gzip, entry CSS gzip, 최대 이미지 용량을 검증하며, 실패 시 배포 전 CI가 실패한다.

## 검증

- frontend source contract tests: 목적지 우선순위와 소유권 출처 표시
- frontend lint, test, build, perf:budget
- backend 기존 카드 원장 계약 테스트
- CI YAML 정적 확인
- 로컬 브라우저에서 카드 상세와 알림 화면의 목적지 표시 확인

## 단계

이 문서의 1~3번을 한 변경으로 구현하고 테스트한다. 퍼널 분석은 실제 집계 계약이 확인된 뒤 다음 변경에서 진행한다.
