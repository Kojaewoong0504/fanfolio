# 성장·미션·포인트 통합 확장 설계

## 목적

Fanfolio의 카드 수집 중심 성장 기능을 실제 팬 행동 전반으로 확장한다. 카드팩 개봉, 인증번호 등록, 이벤트 신청, 댓글 참여, 팬 팔로우처럼 서버가 확인한 행동만 성장 이벤트로 기록하고, 미션·업적·XP·레벨·포인트·무료 팬 패스가 같은 이벤트 원장을 소비하게 한다.

포인트는 현금 전환이 불가능한 서비스 포인트다. 팬은 미션·업적·이벤트 보상으로 포인트를 얻고, 고정형 디지털 보상이나 랜덤 카드 뽑기권으로 교환할 수 있다. 구매·환불·현금성 거래는 이번 범위에서 제외한다.

## 검토한 접근

### 접근 A: 기존 업적 모델에 모든 기능을 계속 추가

- 장점: 마이그레이션과 화면 변경이 작다.
- 단점: 반복 가능한 일일·기간 미션과 일회성 업적의 상태 모델이 섞인다. 보상 재수령, 기간 초기화, 운영 통계가 복잡해진다.

### 접근 B: 공통 이벤트 원장 위에 미션·업적·포인트를 분리

- 장점: 실제 행동 기록은 하나로 유지하면서 반복 미션, 일회성 업적, 포인트 거래를 각각 명확한 원장으로 관리할 수 있다. 기존 카드 업적과 팬 패스를 보존할 수 있다.
- 단점: 새 미션 및 포인트 테이블과 관리자 화면이 필요하다.

### 접근 C: 자유 수식 기반 범용 규칙 엔진 도입

- 장점: 운영자가 임의 행동과 복합 조건을 빠르게 만들 수 있다.
- 단점: 부정 수급, 성능, 권한, 감사, 과거 규칙 재현 문제가 커진다. 현재 서비스 규모에 비해 과도하다.

**결정:** 접근 B를 사용한다. 조건은 서버에 등록된 템플릿만 허용하고 자유 SQL·스크립트·임의 수식은 허용하지 않는다.

## 하위 시스템과 구현 순서

### 1. 성장 이벤트 신뢰성

모든 성장의 원천은 `engagement_events`다. 사용자 행동 API는 도메인 데이터와 성장 이벤트를 같은 트랜잭션에 저장하고, 커밋 뒤 공통 작업 큐로 이벤트 처리를 요청한다.

초기 이벤트 종류는 다음으로 제한한다.

| 이벤트 | 원천 | 중복 기준 |
| --- | --- | --- |
| `card_collected` | 인증번호·QR·카드팩·조합 결과 | 소유 카드 ID |
| `card_pack_opened` | 카드팩 개봉 | 개봉 ID |
| `event_applied` | 이벤트 신청 | 신청 ID |
| `event_commented` | 댓글 참여 이벤트 댓글 | 댓글 ID |
| `fan_followed` | 다른 팬 팔로우 | 팔로우 관계 ID |
| `trade_completed` | 카드 거래 완료 | 거래 ID |
| `card_combined` | 카드 조합 완료 | 조합 ID |
| `card_revoked` | 카드 회수 | 소유 카드 ID와 회수 작업 ID |

카드팩 개봉은 현재 생성한 `card_collected` 이벤트를 반드시 큐에 넣는다. `card_pack_opened`는 개봉 횟수 미션을 위한 별도 이벤트이며 카드 수집 XP와 중복되지 않는다.

이벤트 작업은 실패 시 `pending`을 유지하거나 `failed`와 오류 정보를 기록하고 재처리할 수 있어야 한다. 같은 이벤트를 반복 처리해도 XP, 미션 진행, 업적, 포인트, 팬 패스 보상이 중복되지 않는다.

### 2. 미션과 업적

업적은 팬 계정 전체 기간에 한 번 달성하는 수집·활동 이정표다. 미션은 운영 기간 안에 수행하는 반복 가능 목표다. 두 기능은 같은 이벤트를 소비하지만 정의와 진행 상태를 분리한다.

#### 미션 데이터

- `mission_definitions`: 범위, 제목, 설명, 이벤트 종류, 목표 수치, 반복 주기, 기간, 보상, 검수 상태
- `mission_progress`: 사용자, 미션, 기간 인스턴스, 진행값, 완료·수령 시각
- 반복 주기: `once`, `daily`, `weekly`, `season`
- 상태: `draft`, `pending_review`, `published`, `disabled`, `ended`

#### 초기 조건 템플릿

- 카드 N장 수집
- 카드팩 N회 개봉
- 이벤트 N회 신청
- 댓글 참여 이벤트에 N회 댓글 작성
- 다른 팬 N명 팔로우
- 거래 N회 완료
- 카드 조합 N회 완료
- 특정 아티스트·시즌·카드팩 범위에서 위 행동 수행

업적은 기존 카드 조건을 유지하고 위 활동 이벤트 중 운영 승인을 받은 누적형 템플릿을 추가한다. 이미 완료한 업적은 정의 수정으로 되돌리지 않는다. 공개 후 조건이나 보상을 바꾸려면 새 버전을 만든다.

미션 진행은 실제 서버 행동이 성공한 뒤에만 증가한다. 댓글 삭제, 팔로우 취소처럼 취소 가능한 행동은 기본적으로 완료 상태를 되돌리지 않으며, 부정행위 또는 관리자 회수만 별도 상쇄 이벤트로 처리한다.

### 3. XP·레벨·포인트

#### XP와 레벨

- `xp_ledger`는 불변 원장을 유지한다.
- XP 정책은 이벤트 종류와 운영 규칙별로 버전 관리한다.
- 기본 레벨 곡선은 현재 100 XP 고정식을 제거하고 `level_thresholds` 설정으로 관리한다.
- 이미 지급된 XP는 정책 변경으로 소급 수정하지 않는다.
- 카드 회수나 운영 취소는 음수 원장을 추가한다.

초기 기본 XP는 카드 수집 30 XP만 유지한다. 댓글, 팔로우, 이벤트 신청 같은 반복 행동은 기본 XP를 직접 주지 않고 미션 완료 보상으로만 XP를 지급해 반복 수급을 제한한다.

#### 포인트

- `point_ledger`: 적립·사용·취소·만료를 모두 불변 행으로 기록한다.
- `point_balances`: 조회 최적화용 잔액 캐시다.
- 모든 원장 행은 사용자, 금액, 종류, 원천 이벤트, 규칙 키, 만료일, 설명을 가진다.
- 같은 원천 이벤트와 규칙 키는 한 번만 적립된다.
- 잔액보다 큰 사용은 트랜잭션 잠금으로 거절한다.
- 취소는 기존 행을 수정하지 않고 반대 부호 원장을 추가한다.

초기 사용처는 고정형 디지털 보상과 카드 뽑기권이다. 뽑기권 교환은 포인트를 차감하고 양도 불가능한 티켓 보상을 지급한다. 실제 카드팩 개봉은 기존 공개 확률과 발급 원장을 그대로 사용한다.

### 4. 관리자와 팬 화면

#### 관리자 웹

기존 `팬 성장` 하위에 다음 화면을 연결한다.

- 미션 관리: 목록, 범위·기간·반복 주기·조건·보상 작성, 검수 요청, 공개
- 업적 관리: 기존 카드 조건과 새 활동 조건, 버전·검수 상태
- XP·레벨 정책: 이벤트별 XP와 레벨 임계값 미리보기, 새 버전 공개
- 포인트 정책: 적립 규칙, 만료 정책, 교환 상품, 감사 내역
- 운영 현황: 처리 실패 이벤트, 수동 재처리, 미션 완료율, 포인트 발행·사용·만료

루트와 플랫폼 운영자는 전역 정책을 관리한다. 파트너 관리자는 자기 조직·아티스트 범위의 미션과 보상만 초안 작성하고 검수 요청할 수 있다. 공개, 수동 포인트 조정, 실패 이벤트 재처리는 별도 권한과 감사 로그를 요구한다.

#### 팬 앱

- 성장 화면: 레벨, XP, 포인트 잔액, 진행 중 미션, 완료·수령 상태
- 미션 전체 화면: 진행 중·완료·종료 필터, 기간과 보상 표시
- 포인트 내역 화면: 적립·사용·취소·만료 내역
- 포인트 교환 화면: 고정 보상과 뽑기권, 잔액 부족 상태
- 행동 완료 화면: 카드 등록·카드팩 개봉·이벤트 신청 후 증가한 미션과 보상을 요약

화면은 기존 Fanfolio 디자인 시스템과 하단 내비게이션을 유지한다. 포인트는 마이 프로필 요약과 성장 화면에서 같은 서버 잔액을 사용한다.

## 데이터 흐름

```text
팬 행동 API 성공
  → 도메인 데이터 + engagement_event 동일 트랜잭션 저장
  → 공통 작업 큐 enqueue
  → 이벤트 멱등 잠금
  → XP 정책 평가
  → 미션 진행 평가
  → 업적 진행 평가
  → 포인트·보상 지급
  → 팬 패스 진행 갱신
  → 알림·감사·분석 이벤트 기록
  → processed
```

팬 API는 이벤트 처리 전후 상태를 구분한다. 행동 직후 처리 중이면 낙관적으로 가짜 보상을 표시하지 않고 `반영 중` 상태를 보여 준다. 처리 실패는 사용자 행동 자체를 취소하지 않으며 운영 재처리 대상으로 남긴다.

## 오류와 부정 수급 방지

- 사용자 요청의 XP·포인트·진행값을 신뢰하지 않는다.
- 이벤트, XP, 포인트, 보상, 미션 수령에 각각 유니크 멱등 키를 둔다.
- 반복 행동 미션에는 사용자·행동별 합리적인 일일 상한을 둔다.
- 삭제·취소 가능한 콘텐츠와 완료 판정 정책을 정의별로 고정한다.
- 포인트 수동 조정과 이벤트 재처리는 사유 입력과 감사 로그를 필수로 한다.
- 포인트 잔액은 원장 합계와 캐시를 정기적으로 대조할 수 있어야 한다.
- 공개된 미션·포인트·XP 정책은 수정하지 않고 새 버전으로 교체한다.

## 테스트와 완료 기준

각 하위 시스템은 독립적으로 배포 가능한 수직 슬라이스로 구현한다.

1. 카드팩 개봉 후 카드 수집 이벤트가 처리되어 XP·레벨·팬 패스가 정확히 한 번 증가한다.
2. 댓글, 이벤트 신청, 팔로우, 거래, 조합 성공이 해당 미션만 증가시키고 실패·중복 요청은 증가시키지 않는다.
3. 일일·주간 미션은 기간 인스턴스가 바뀔 때 새 진행 상태를 만들고 과거 수령 내역을 보존한다.
4. 미션 완료 보상 XP·포인트·디지털 보상이 한 번만 지급된다.
5. 포인트 적립·사용·취소·만료 후 잔액이 원장 합계와 일치하고 음수 잔액이 발생하지 않는다.
6. 공개 전·범위 밖 미션과 정책은 팬 또는 다른 파트너 관리자에게 노출되지 않는다.
7. 관리자가 공개 정책을 직접 수정할 수 없고 새 버전·검수 흐름을 거쳐야 한다.
8. 팬 앱의 마이 페이지, 성장 화면, 미션 화면, 포인트 내역이 같은 실제 잔액과 진행 상태를 표시한다.
9. 작업 큐가 중단된 상태에서 만든 이벤트를 재처리하면 누락 없이 반영되고 중복 보상은 없다.
10. 로컬 전체 시나리오에서 관리자 미션 공개 → 팬 행동 → 미션 완료 → 포인트 적립 → 뽑기권 교환 → 카드팩 개봉 → 컬렉션·레벨 반영이 완료된다.

## 범위 밖

- 포인트 구매·현금화·환불
- 포인트의 팬 간 양도
- 자유 SQL·스크립트 기반 미션 조건
- 외부 SNS 좋아요·공유처럼 서버가 직접 검증할 수 없는 행동
- 유료 팬 패스와 결제
- 실물 경품 배송

## 분할 실행

전체 범위는 다음 네 작업 묶음으로 순차 구현한다.

1. 성장 이벤트 신뢰성과 카드팩 누락 수정
2. 범용 미션·업적·XP 정책
3. 포인트 원장·교환
4. 관리자·팬 화면과 전체 E2E

각 묶음은 실패 테스트, 최소 구현, 회귀 테스트, 마이그레이션 검증을 통과한 뒤 다음 묶음으로 넘어간다.
