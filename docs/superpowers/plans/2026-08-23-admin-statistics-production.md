# 관리자 통계 운영 연결 구현 계획

**Goal:** 실제 카드·팬 활동 데이터로 관리자 통계 화면을 구동하고 역할별 범위를 검증한다.

**Architecture:** 기존 원장 테이블 집계에 새 `analytics_events` 행동 원장을 결합한다. 단일 통계 API가 필터 선택지와 모든 위젯 데이터를 반환하며 관리자 웹은 같은 응답을 ROOT/파트너 레이아웃에 투영한다.

## Task 1: 권한·이벤트 원장 계약

- `statistics:read` 역할 계약 테스트를 추가한다.
- `AnalyticsEvent` 모델과 0049 마이그레이션을 추가한다.
- 중복 방지 이벤트 기록 helper와 단위 테스트를 추가한다.

## Task 2: 사용자 행동 계측

- 인증번호 인식·성공·실패를 기록한다.
- 카드팩 개봉을 기록한다.
- 카드 상세 조회를 컬렉션 확인으로 기록한다.
- 기존 비즈니스 응답과 멱등성을 보존한다.

## Task 3: 통계 API

- 실패하는 ROOT·파트너 범위/기간/집계 계약 테스트를 먼저 작성한다.
- `/api/admin/statistics` 집계와 필터 검증을 구현한다.
- 과거 원장 집계와 이벤트 추적 시작 시점을 함께 반환한다.

## Task 4: 관리자 웹 연결

- 정식 통계 메뉴와 상태를 추가한다.
- API 로더, 로딩·오류·빈 상태를 추가한다.
- 기존 프리뷰 렌더러를 fixture/API 공용 데이터 렌더러로 정리한다.

## Task 5: 검증

- 백엔드 계약 테스트와 전체 관리자 테스트를 실행한다.
- 로컬 서버에서 ROOT/파트너 통계 API를 비교한다.
- 인앱 브라우저에서 정식 통계 메뉴, 필터, 실제 집계를 검증한다.
- 빌드와 diff 검사를 통과시킨다.
