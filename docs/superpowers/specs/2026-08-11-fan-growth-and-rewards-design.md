# 팬 성장·업적·무료 팬 패스 설계

## 목적

Fanfolio를 카드 보관 화면에 머물지 않고, 공식 카드를 수집한 팬이 자신의 활동을 확인하고 성취를 표현하는 서비스로 확장한다. 핵심 루프는 **공개 카드 수집 → 업적·미션 달성 → XP·레벨 성장 → 꾸미기 보상 장착 → 다음 공식 드롭 참여**다.

이 기능은 기존의 아티스트 스튜디오 → 회사 검수 → 드롭·코드 → 팬 소유권 등록 흐름 뒤에만 작동한다. 공개 전 카드, 검수 중 카드, 취소된 드롭은 성장 보상을 만들지 않는다.

## 제품 원칙

- 첫 출시의 `팬 패스`는 무료다. 유료 패스·결제·확률형 보상은 범위에서 제외한다.
- XP와 보상은 브라우저가 아니라 서버가 확정한다. 팬 앱은 결과를 표시하고 수령 요청만 한다.
- 카드 보상은 현금성·양도성 보상보다 뱃지, 칭호, 프로필 프레임, 컬렉션 테마처럼 안전한 꾸미기 보상을 우선한다.
- 일일 접속이나 과도한 연속 출석보다 공식 카드 수집과 아티스트별 컬렉션 완성에 가치를 둔다.
- 다른 팬의 수집 내역, 닉네임, 순위는 기본 공개하지 않는다. 공개 프로필은 팬이 직접 켠 항목만 노출한다.

## 출시 범위와 후속 범위

| 단계 | 포함 기능 | 제외 기능 |
| --- | --- | --- |
| 출시 마무리 | 카드-드롭 연결, 최종 승인, 코드 배치, 팬 노출, QR/코드 등록 E2E | 성장 보상 |
| Fan Growth v1 | 프로필 장착, 아티스트·카드 수집 업적, XP 원장, 레벨, 알림 | 유료 패스, 랭킹, 거래 |
| Fan Pass v1.1 | 무료 시즌 패스, 티어 보상, 아티스트 공동 목표 | 결제, 랜덤 상자, 교환 시장 |
| Live Ops v2 | 기간 한정 미션, 팬덤 공동 이벤트, 선택적 쇼케이스 | 친구 경쟁, 공개 리더보드 기본값 |

출시 마무리를 먼저 끝내야 실제 카드 등록 이벤트로 성장 기능을 검증할 수 있다. 다만 Fan Growth v1의 데이터 모델과 이벤트 계약은 카드·드롭 릴리스 작업과 함께 설계한다.

## 팬 경험

### 1. 홈: 오늘의 팬 활동

기존 홈/컬렉션 상단에 다음 정보를 한 장의 활동 카드로 보여 준다.

- 현재 레벨과 누적 XP, 다음 레벨까지의 진행도
- 진행 중인 아티스트 업적 최대 3개
- 시즌 패스 진행도와 수령 가능한 보상 수
- 새로 열린 뱃지·칭호 알림

하단 내비게이션은 기존 5개를 유지한다. 패스를 별도 여섯 번째 탭으로 추가하지 않고, 홈의 활동 카드와 프로필 화면에서 진입한다.

### 2. 업적

업적은 전체 서비스, 파트너 회사, 아티스트, 멤버, 카드 세트 중 하나에 귀속된다. 팬에게는 진행률·보상·종료일을 명확히 보여 준다.

초기 조건은 운영자가 조합할 수 있는 안전한 템플릿으로 한정한다.

| 템플릿 | 예시 |
| --- | --- |
| 첫 공식 카드 수집 | 드림스케이프 첫 카드 등록 |
| 카드 수 누적 | 유나 카드 5장 수집 |
| 고유 멤버 수집 | 드림스케이프 멤버 3명 수집 |
| 특정 카드 보유 | 컴백 기념 스페셜 카드 수집 |
| 세트 완성 | 2026 SPRING 9종 완성 |
| 기간 내 공식 드롭 참여 | 여름 컴백 드롭에서 카드 1장 등록 |

초기에는 임의 SQL, 자유 수식, 외부 SNS 행동을 조건으로 허용하지 않는다. 조건 템플릿을 추가하려면 서버 이벤트와 부정 수급 검토를 함께 추가한다.

### 3. 프로필과 표현

팬은 대표 칭호 1개, 대표 뱃지 최대 3개, 프로필 프레임 1개, 컬렉션 테마 1개를 장착한다. 업적을 달성해도 즉시 공개하지 않으며, 기본값은 본인에게만 보이는 상태다. 프로필 공개를 선택한 팬만 장착 항목을 다른 팬에게 보여 줄 수 있다.

### 4. XP·레벨

XP는 이벤트마다 불변 원장으로 기록하고, 레벨은 누적 XP에서 계산한다. 카드 소유권이 취소·회수되면 상쇄 원장을 추가하며 이미 기록된 행을 수정하지 않는다.

초기 XP 정책은 다음처럼 단순하게 시작한다.

| 이벤트 | 기본 XP | 제한 |
| --- | ---: | --- |
| 유효한 새 카드 등록 | 30 | 같은 코드/소유권은 한 번만 |
| 스페셜 카드 등록 | 60 | 같은 카드 소유권은 한 번만 |
| 아티스트 세트 완성 | 150 | 세트·시즌당 한 번만 |
| 업적 달성 | 50 | 업적당 한 번만 |
| 기간 한정 공식 미션 | 정책별 | 사용자·이벤트·규칙 조합 한 번만 |

XP 액수와 레벨 곡선은 운영 설정으로 변경할 수 있지만, 이미 확정된 원장의 XP를 소급 변경하지 않는다.

### 5. 무료 팬 패스

팬 패스는 시즌별 누적 XP를 사용한다. 시작 시점에는 무료 트랙 하나만 제공하며, 티어는 10개 내외로 제한한다. 보상은 뱃지·칭호·프레임·테마·공식 디지털 특전으로 구성한다.

- 시즌 종료 뒤 미수령 보상은 14일 유예 기간 동안 수령할 수 있다.
- 다음 시즌에 XP를 이월하지 않는다. 레벨은 서비스 전체 누적 XP로 계속 유지한다.
- 같은 티어 보상은 한 번만 수령된다.
- 실물 경품, 구매권, 양도 가능한 코드 보상은 v1 범위에서 제외한다.

## 운영자 경험과 권한

### 업적·보상 빌더

관리자 웹에 `팬 성장` 영역을 추가한다. 운영자는 다음 순서로 업적을 만든다.

1. 범위를 선택한다: 플랫폼 전체 / 회사 / 아티스트 / 멤버 / 카드 세트
2. 조건 템플릿과 목표 수치를 선택한다.
3. 보상을 선택한다: XP, 뱃지, 칭호, 프레임, 테마
4. 공개 기간과 대상 아티스트를 확인한다.
5. 미리보기 후 검수 요청한다.

뱃지와 칭호는 카드 제작과 동일하게 초안·검수·공개 버전을 가진다. 운영자는 사전에 등록된 아트워크만 고르며, 이미지 업로드는 기존 자산 검수 정책을 따른다.

| 역할 | 할 수 있는 일 |
| --- | --- |
| 루트 관리자 | 전역 템플릿, 전체 시즌 정책, 예외 승인, 감사 로그 |
| 플랫폼 운영 관리자 | 플랫폼 공통 업적·보상 검수 및 공개 승인 |
| 기업 슈퍼 관리자 | 자기 회사·아티스트 범위의 업적/무료 패스 공개 승인 |
| 기업 매니저 | 회사 범위 초안 작성, 검수 요청, 성과 확인 |
| 기업 에디터 | 초안과 아트워크 편집, 검수 요청만 가능 |
| 아티스트 스튜디오 | 카드용 뱃지/칭호/테마 아이디어와 아트워크 제안, 직접 공개 불가 |

다른 파트너의 업적 정의, 참여 통계, 보상 목록은 API 수준에서 조회·수정할 수 없다.

## 기존 카드 릴리스와의 연결

```text
Artist Studio 카드 초안
  → 회사 검수
  → (Special이면 플랫폼 운영 검수)
  → approved
  → 드롭 연결 및 코드 배치
  → published / 라이브 드롭
  → 팬 QR·코드 등록
  → card_collected 이벤트
  → 업적·미션 평가
  → XP 원장·보상 지급·알림
```

카드가 공개됐다는 사실만으로 XP를 지급하지 않는다. 팬별 소유권이 정상적으로 생성됐을 때에만 이벤트를 발행한다. 드롭 공개, 카드 회수, 소유권 취소도 이벤트로 남겨 운영자가 결과를 추적할 수 있게 한다.

## 데이터와 API 경계

### 핵심 데이터

| 엔터티 | 책임 |
| --- | --- |
| `engagement_events` | 소유권 등록, 세트 완성 등 원본 이벤트와 멱등 키 |
| `achievement_definitions` | 범위·조건 템플릿·목표·기간·검수 상태 |
| `achievement_progress` | 팬별 진행도와 달성 시각 |
| `reward_catalog` | 뱃지·칭호·프레임·테마의 메타데이터와 자산 |
| `reward_grants` | 팬에게 실제 지급된 보상 및 수령 시각 |
| `xp_ledger` | XP 발생·상쇄 원장, 관련 이벤트와 규칙 |
| `fan_levels` | 누적 XP에서 계산된 현재 레벨 캐시 |
| `pass_seasons`, `pass_tiers`, `pass_progress` | 무료 패스와 티어 수령 상태 |
| `profile_equipment` | 팬이 선택한 대표 칭호·뱃지·프레임·테마 |

모든 보상 지급에는 `(user_id, source_event_id, reward_rule_id)` 유니크 키를 둔다. 같은 요청을 재시도하거나 작업자가 중복 실행돼도 XP와 보상이 두 번 지급되지 않는다.

### 외부 API 초안

| 사용자 | API | 목적 |
| --- | --- | --- |
| 팬 | `GET /api/me/progression` | 레벨, XP, 패스 요약 |
| 팬 | `GET /api/me/achievements` | 업적 목록, 진행률, 보상 |
| 팬 | `GET /api/me/rewards` | 보유·수령 가능 보상 |
| 팬 | `POST /api/me/rewards/{grant_id}/claim` | 수령 가능한 보상 확정 |
| 팬 | `PUT /api/me/profile/equipment` | 칭호·뱃지·프레임 장착 |
| 관리자 | `GET/POST/PATCH /api/admin/engagement/achievements` | 범위 내 업적 초안 관리 |
| 관리자 | `POST /api/admin/engagement/achievements/{id}/submit-review` | 검수 요청 |
| 승인자 | `POST /api/admin/engagement/achievements/{id}/approve` | 역할별 공개 승인 |
| 관리자 | `GET/POST/PATCH /api/admin/engagement/pass-seasons` | 무료 시즌 패스 관리 |

내부 이벤트는 `card.redeemed`, `collection.completed`, `card.revoked`, `drop.published` 같은 이름을 사용한다. 이벤트 소비·보상 지급·알림 생성은 outbox와 비동기 작업자로 처리하되, 카드 등록 API의 성공 여부는 소유권 저장과 분리하지 않는다.

## 보안·부정 수급 방지

- QR/코드 등록 API가 정상 카드 소유권을 만든 뒤에만 성장 이벤트를 발행한다.
- XP, 진행도, 보상 권한은 요청 본문을 신뢰하지 않고 서버 데이터로 계산한다.
- 중복 코드 등록, 재시도, 비동기 작업 재처리는 멱등 키로 한 번만 보상한다.
- 비정상적으로 빠른 코드 등록은 기존 레이트 리밋과 감사 로그에 기록한다.
- 운영자가 업적 조건·XP·보상을 수정하면 새 버전을 만들고, 이미 지급된 결과는 감사 로그에서 추적한다.
- 관리자 범위, 승인, 보상 수동 지급, XP 상쇄는 모두 행위자·조직·사유를 감사 로그에 남긴다.

## 화면 구성

| 화면 | 핵심 요소 |
| --- | --- |
| 팬 홈 | 레벨 진행도, 오늘의 업적, 수령 가능 보상, 패스 요약 |
| 팬 프로필 | 대표 칭호·뱃지·프레임 장착, 공개 범위 설정 |
| 업적 전체 보기 | 아티스트 필터, 진행률, 완료/기간 종료 상태 |
| 팬 패스 | 시즌 남은 기간, 티어 보상, 수령 버튼 |
| 관리자 팬 성장 | 업적 빌더, 보상 자산, 검수 대기열, 시즌 패스 설정 |
| 아티스트 스튜디오 | 카드에 연결할 행사 뱃지/테마 제안 상태 |

## 검증 기준

1. 유효한 코드로 새 카드를 등록하면 `card_collected` 이벤트, XP 원장, 해당 업적 진행도가 한 번씩만 생성된다.
2. 같은 코드 등록 요청과 이벤트 작업을 반복해도 XP·뱃지·칭호가 중복 지급되지 않는다.
3. 카드 회수 시 상쇄 원장이 남고, 취소 정책이 허용하는 업적/보상만 변경된다.
4. 아티스트·회사 범위 밖의 관리자는 업적·보상·패스 정의를 조회하거나 수정할 수 없다.
5. 검수 전 업적과 시즌 보상은 팬 API에 노출되지 않는다.
6. 팬은 획득한 보상만 장착할 수 있고, 비공개 프로필은 다른 팬에게 노출되지 않는다.
7. 무료 패스 티어 보상은 조건 충족 뒤 한 번만 수령되며 시즌 종료 유예 기간 후에는 수령할 수 없다.
8. Special 카드가 승인·드롭 연결·공개된 뒤 팬이 수집했을 때, 관련 아티스트 업적과 패스 진행이 정상 반영된다.

## 구현 순서

1. 카드-드롭 직접 연결과 최종 승인, 코드 배치, 팬 노출을 완료하고 E2E를 다시 통과시킨다.
2. `engagement_events`, `xp_ledger`, `profile_equipment`과 팬 진행도 API를 추가한다.
3. 카드 수집·세트 완성 템플릿만 가진 업적 v1과 보상 장착 화면을 만든다.
4. 관리자 업적 빌더와 회사 범위 검수·공개 흐름을 추가한다.
5. 무료 팬 패스와 티어 수령, 시즌 종료 처리를 추가한다.
6. 지표와 부정 수급 데이터를 확인한 뒤 기간 한정 미션·공동 목표를 확장한다.

- 유료 팬 패스, 결제, 환불, 확률형 보상
