# 팬앱 프론트엔드 연동·검증 백로그

> 백엔드에 추가된 카드·보상·소셜 기능이 팬앱에서 실제 서비스 흐름으로 완성되었는지 확인하기 위한 작업 문서입니다.

## 문서 목적

현재 Fanfolio는 백엔드 API와 팬앱의 1차 화면 연결이 상당 부분 진행되어 있습니다. 다만 소스 계약 테스트나 개별 화면 구현만으로는 다음을 보장할 수 없습니다.

- 실제 데이터가 화면에 올바르게 표시되는가
- 성공·실패·빈 상태·재시도 상태가 자연스럽게 처리되는가
- 관리자 웹에서 생성한 데이터가 팬앱까지 연결되는가
- 카드 발급 후 컬렉션·알림·획득 이력이 일관되게 갱신되는가
- 모바일 환경과 실기기에서 카드·QR·미디어 상호작용이 동작하는가

따라서 이 문서는 “백엔드 기능 존재 여부”가 아니라 “팬앱에서 실제 사용 가능한가”를 기준으로 관리합니다.

## 상태 기준

- `[ ] 미검증` — 코드 또는 API는 있으나 실제 프론트 흐름을 확인하지 않음
- `[~] 부분 구현` — 기본 UI 또는 API 연결은 있으나 서비스 수준의 상태 처리가 부족함
- `[x] 검증 완료` — 실제 데이터로 핵심 성공·실패 흐름을 확인함
- `[!] 차단` — 외부 환경, 권한, 실기기 또는 백엔드 보완이 필요함

## 2026-08-22 최신 판정

- 확정 완료: 카드팩·QR/인증번호·보상·알림 기본 흐름, 카드 상세 독립 라우트·메타데이터·뒷면 틸트, 보호 음성 재생, 미디어 실패 fallback.
- 계약·회귀 완료: 카드 조합 소비·멱등성·확률, 거래 소유권 이전·제약, 조합/거래 알림 이벤트, QR 실패 fallback.

- 최신 자동 검증: frontend `158 passed`, backend P0 contract `84 passed, 1 warning`, P1 combination/social/trade contract `7 passed, 1 warning`, `npm run build`, `npm run lint`(기존 warning 4건), backend Ruff, `git diff --check` 통과.
- 새 인앱 브라우저 세션에서 이메일 회원가입→아티스트/멤버/닉네임 온보딩을 직접 완료했다. 인증번호 등록에서 `INVALID-0000`을 입력해 카드 확인 단계가 열리는 현재 UX를 확인했고, 최종 `이 카드 등록하기`에서 `코드를 찾을 수 없습니다.`로 차단되는 것까지 재확인했다. QR 경로는 같은 세션에서 카메라 스트림 시작 및 `인증 코드 직접 입력` fallback을 재확인했다.

- 카드 상세의 실제 모바일 touch swipe와 카메라 권한 거부·미지원 브라우저는 인앱 브라우저만으로 증명할 수 없다. 정상 카메라 스트림과 직접 입력 fallback은 확인했으므로, 이 항목들은 실기기 또는 권한 제어가 가능한 브라우저에서 별도 검증해야 한다.
- 따라서 이번 재검증 후에도 P0 전체를 `[x]`로 올리지 않는다. 남은 항목은 유효 영상 fixture, 조합/거래 데이터 fixture, 실기기 touch·카메라 예외 검증이다.
