# Fanfolio 운영 안정화 및 CS MVP 설계

## 목표

출시 전 핵심 운영 흐름을 검증하고, 팬 문의를 접수·처리하며, 외부 알림 전달 실패와 팬 간 거래·소셜 위험을 운영자가 확인할 수 있게 한다.

## 범위

1. 관리자 카드 업로드부터 팬앱 반영까지의 통합 검증 계약
2. 팬 문의/신고 접수와 관리자 답변 큐
3. 알림 전달 상태·재시도·최종 실패 운영 화면과 수동 재처리
4. 거래 동시성·만료·차단·팔로우 상태의 회귀 검증
5. 운영 문서와 출시 게이트 상태 정리

## 설계

### CS 데이터

`support_tickets`는 문의의 현재 상태를, `support_messages`는 팬과 운영자의 대화 이력을 보관한다. 문의 유형은 `general`, `card`, `trade`, `order`, `report`로 제한한다. 상태는 `open`, `in_progress`, `answered`, `closed`로 제한하고, 모든 관리자 상태 변경과 답변은 `AuditLog`에 기록한다.

팬은 자신의 티켓만 조회하고 새 티켓을 생성할 수 있다. 관리자는 권한 범위와 관계없이 CS 큐를 조회하고 답변·상태 변경을 수행한다. 답변은 기존 인앱 알림을 만들고, 이메일은 기존 `NotificationDelivery` outbox를 통해 선택적으로 전달한다.

### 운영 큐

관리자 화면에 고객센터와 전달 실패 큐를 추가한다. 전달 실패 큐는 기존 `notification_deliveries`를 재사용하며, 비밀값·토큰·본문의 민감정보는 화면과 로그에 노출하지 않는다.

### 소셜 안전성

기존 `Follow`, `UserBlock`, `TradeLock`를 유지한다. 거래 수락은 이미 잠긴 제안에 대해 단일 상태 전이만 허용하고, 차단 관계가 생기면 공개 컬렉션·검색·신규 거래·팔로우가 모두 거부된다. 회귀 테스트로 이 계약을 고정한다.

## 검증 기준

- 카드 운영 통합 시나리오가 이미지 업로드를 포함해 테스트된다.
- 팬이 문의를 생성하고 관리자 답변을 확인할 수 있다.
- 답변에 대한 인앱 알림이 생성되고 전달 outbox가 중복 없이 기록된다.
- 관리자에게 전달 실패 상태와 재시도 결과가 보인다.
- 거래 중복 수락, 만료 거래, 차단 후 접근이 모두 차단된다.
- 전체 백엔드·프론트엔드·관리자 테스트와 빌드가 통과한다.
