# Browser Annotation Round Two Design

## Goal

주석으로 확인된 팬앱, 관리자 웹, 아티스트 스튜디오의 정보 구조와 화면 밀도 문제를 실제 서비스 수준으로 정리한다. 기존 API, 권한, 카드 제작·검수 흐름은 유지하고 사용자가 이해하기 어려운 중복 정보와 개발자용 설명을 제거한다.

## Scope

### Fan app

- 로그인 화면의 브랜드 로고, 제목, 설명을 화면 중앙 축에 정렬한다.
- 하단 메뉴는 `탐색 · 보관함 · 홈 · 팬 레벨 · 마이`의 다섯 항목으로 유지한다.
- `홈`을 가운데 배치하고 앱의 서비스 소식과 관심 아티스트 진입점으로 사용한다.
- 기존 `컬렉션`과 `보관함`의 중복 역할은 `보관함`으로 통합한다.
- 홈은 기존 API의 알림, 아티스트 카탈로그, 공개 카드 카탈로그를 조합해 다음 정보를 제공한다.
  - 진행 중이거나 최근 시작된 서비스 이벤트/드롭
  - 관심 아티스트 또는 온보딩에서 선택한 아티스트
  - 해당 아티스트의 신규 공개 카드
- 별도 백엔드 API를 추가하지 않고 현재 데이터 계약 안에서 구성한다.

### Admin web

- 검수 목록 패널과 상세 패널의 상단 기준선, 높이, 내부 여백을 맞춘다.
- 검색 입력의 폰트와 플레이스홀더 크기를 테이블 밀도에 맞게 줄인다.
- 카드 목록은 서버의 `page`, `pageSize`, `q`, `status` 기능을 사용한다.
- 상태 필터에서 `공개됨`을 명시적으로 선택할 수 있게 하고 필터가 전체 페이지 결과에 적용되게 한다.
- 사용자·감사 로그와 동일한 방식으로 카드 목록 페이지네이션을 제공한다.
- 상세 패널의 효과 미리보기는 제목, 켜짐 상태, 프리셋, 강도, 상호작용을 짧은 행/칩으로 정리한다.
- 카드 이미지와 중복되는 `제출 스냅샷` 텍스트 그리드는 제거한다.
- 앞면·뒷면·추가 미디어 존재 여부는 상세 상단의 작은 미디어 액션으로 표시한다.
- 카드 공개는 기존 권한과 드롭 연동 계약을 유지한다. 승인된 카드에는 다음 단계가 `드롭 연결` 또는 `공개 준비`임을 명확히 표시하고 실행 버튼을 상세 상단 액션 영역에 둔다.
- 행 전체 클릭과 키보드 Enter/Space 활성화는 유지한다.

### Artist studio

- 로그인 화면의 HttpOnly, 메모리 토큰 등 개발자용 보안 설명을 제거한다.
- 설정 화면은 표시 이름, 로그인 아이디, 연결 이메일, 이메일 알림, 저장, 로그아웃만 제공한다.
- Access Token, Refresh Token, RTR 등 구현 세부 정보 카드를 제거한다.
- 설정의 이메일 알림 체크박스는 일반적인 18px 수준의 컨트롤로 제한하고 행 전체가 과도하게 확대되지 않게 한다.
- 사이드바 프로필 버튼은 데스크톱에서 최소 56px 높이와 충분한 가로 클릭 영역을 확보한다.
- `내 카드`, `팬 반응`, `설정`은 셸 상단 제목만 사용하고 내부의 중복 페이지 제목 블록을 제거한다.
- `새 카드 만들기`는 내 카드 콘텐츠 상단 우측의 독립 액션으로 배치한다.
- 기존 모바일·태블릿 내비게이션과 편집기 반응형 동작은 유지한다.

## Architecture and Data Flow

### Fan navigation

현재 탭 상태와 라우팅 방식을 유지하되, `home`은 서비스 홈, `collection`은 보관함으로 의미를 변경한다. 홈은 이미 로드하는 알림 및 카탈로그 데이터를 파생해 섹션을 구성한다. 데이터가 없으면 빈 이벤트를 꾸미지 않고 아티스트 탐색 CTA를 보여준다.

### Admin pagination and filtering

카드 목록에 `cardPage`, `cardPagination` 상태를 추가한다. 검색어 또는 필터가 바뀌면 첫 페이지로 돌아가고 `/admin/cards` 요청에 서버 파라미터를 전달한다. 페이지 이동은 사용자·감사 로그의 기존 페이지네이션 패턴을 재사용한다. 선택된 상세 카드는 페이지 이동 후 목록에 없으면 닫는다.

### Studio view hierarchy

셸의 상단 제목을 페이지의 단일 제목으로 삼는다. 각 화면 내부는 제목을 반복하지 않고 콘텐츠 툴바 또는 데이터 카드부터 시작한다. 설정 로그아웃은 별도 보안 설명 없이 프로필 폼 하단의 위험 액션으로 제공한다.

## Interaction and Accessibility

- 하단 메뉴는 다섯 개를 동일한 폭으로 유지하고 중앙 홈의 활성 상태가 명확해야 한다.
- 관리자 페이지네이션과 상태 필터는 키보드로 사용할 수 있어야 한다.
- 관리자 행 안의 버튼, 링크, 셀렉트 조작은 행 클릭을 중복 실행하지 않는다.
- 미디어 액션은 아이콘만 쓰지 않고 접근 가능한 이름을 제공한다.
- 스튜디오 체크박스의 입력 자체와 라벨 행 모두 클릭 가능해야 한다.
- 중복 제목 제거 후에도 각 화면에는 하나의 명확한 `h1` 또는 동등한 페이지 제목이 남아야 한다.

## Responsive Behavior

- 팬앱 로그인은 320px 이상에서 좌우 여백을 유지하면서 중앙 정렬한다.
- 관리자 1120px 이상에서는 목록과 상세를 나란히 두고 같은 상단선에 맞춘다.
- 관리자 1119px 이하에서는 목록과 상세를 한 열로 쌓고 내부 가로 스크롤을 만들지 않는다.
- 스튜디오는 기존 데스크톱 사이드바, 태블릿 축소 사이드바, 모바일 하단 내비게이션 규칙을 보존한다.

## Error and Empty States

- 팬 홈 이벤트 데이터가 없으면 관심 아티스트 탐색과 공개 카드 탐색으로 연결한다.
- 관리자 목록 요청 실패 시 기존 오류 메시지와 재시도 흐름을 유지한다.
- 관리자 페이지 이동 후 항목이 없으면 가능한 마지막 페이지로 복구하거나 빈 결과를 명확히 표시한다.
- 스튜디오 프로필 저장 오류와 성공 메시지는 기존 동작을 유지한다.

## Testing

### Fan app

- 로그인 로고/제목 중앙 정렬 CSS 계약
- 다섯 메뉴 순서와 중앙 홈
- 컬렉션/보관함 중복 라벨 제거
- 홈 이벤트·아티스트·신규 카드 섹션 및 빈 상태
- 기존 로그인, 카드 상세, 팬 레벨 회귀 테스트

### Admin web

- 카드 요청의 페이지·검색·상태 파라미터
- 필터 변경 시 첫 페이지 복귀
- 공개됨 상태 필터
- 이전/다음 페이지 동작과 비활성 조건
- 목록/상세 상단 정렬 CSS 계약
- 축약된 효과 요약과 제출 스냅샷 제거
- 승인 카드의 드롭 연결/공개 준비 액션
- 행 클릭 및 키보드 접근성 회귀 테스트

### Artist studio

- 로그인 보안 개발 문구 제거
- 토큰/세션 설명 제거 및 로그아웃 유지
- 설정 필드와 알림 체크박스 유지
- 내부 중복 페이지 제목 제거
- 내 카드의 새 카드 만들기 액션 유지
- 프로필 버튼과 체크박스 크기 CSS 계약
- 데스크톱·태블릿·모바일 회귀 테스트

## Out of Scope

- 새로운 인증 또는 세션 보안 방식
- 새로운 이벤트/드롭 백엔드 모델
- 카드 공개 권한 정책 변경
- 팬앱 컬렉션 데이터 모델 변경
- 스튜디오 편집기 기능의 추가 변경

## Acceptance Criteria

- 사용자가 지적한 18개 주석이 각각 화면 구조, 정보 제거, 필터/페이지네이션 또는 정렬 수정으로 대응된다.
- 같은 화면에서 동일 페이지 제목이 두 번 표시되지 않는다.
- 관리자에서 공개된 카드를 상태 필터로 찾고 페이지를 이동할 수 있다.
- 카드 공개 흐름의 다음 작업을 상세 패널에서 이해하고 실행할 수 있다.
- 팬앱의 중앙 홈과 보관함 역할이 이름과 콘텐츠로 명확히 구분된다.
- 세 앱의 기존 테스트, 새 회귀 테스트, 린트/빌드가 통과한다.
- 데스크톱, 태블릿, 모바일 주요 뷰포트에서 가로 오버플로와 잘린 컨트롤이 없다.
