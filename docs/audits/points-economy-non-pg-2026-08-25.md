# 포인트 경제·비-PG 상점 구현 기록

## 결정

사업자 등록과 PG/간편결제 계약 전까지 외부 결제수단은 제공하지 않는다. 현재 상점은 포인트 결제만 허용하고, 포인트 지급·차감·환불과 상품 지급은 하나의 데이터베이스 트랜잭션으로 처리한다.

## 구현 범위

- 관리자 포인트 조정은 `idempotencyKey`별로 한 번만 원장을 만든다.
- 상점 주문은 `Idempotency-Key`와 주문 고유키를 함께 기록해 재시도 시 중복 차감·중복 주문을 막는다.
- 환불은 완료 주문만 가능하고, 원래 차감 원장을 역전하는 `reverse` 원장을 한 번만 만든다.
- 환불된 주문은 다시 환불할 수 없으며, 동일 멱등키 재요청은 최초 응답과 동일한 결과를 반환한다.
- 카드팩 환불은 아직 열지 않은 구매 사용권만 가능하며, 사용권은 환불과 함께 폐기된다.
- 포인트/한정 보상 상품은 미수령 보상만 환불과 함께 `revoked_at`으로 무효화하고, 이미 수령한 보상은 환불을 거부한다.
- 카드팩 상품은 기존 카드팩 연결을 사용한다.
- `point_item`과 `limited_item`은 관리자가 공개 `RewardCatalog` 보상을 연결하면 주문 완료와 동시에 `RewardGrant`를 생성한다.
- 상품 상세 콘텐츠와 보상 연결 정보는 관리자 상품 데이터와 팬앱 상품 상세 API에 함께 노출된다.
- 관리자 상품 등록에서 카드팩·포인트 상품·한정 상품 유형을 선택하고 공개 보상 또는 카드팩을 연결할 수 있다.
- 팬앱 상점 주문 내역에서 포인트 환불을 요청하고 환불 상태를 확인할 수 있다.

## 의도적으로 제외한 범위

- PG사 결제 승인·취소
- 신용카드, 카카오페이, 네이버페이 연동
- 외부 결제 webhook 및 결제기관 대사

## 데이터 원자성 규칙

포인트 잔액 잠금, 포인트 원장, 포인트 거래 기록, 주문 상태, 상품 지급을 같은 세션 트랜잭션에서 처리한다. 중간 단계에서 실패하면 전체가 롤백되어 잔액만 차감되거나 상품만 지급되는 상태를 만들지 않는다.

## 검증

- 포인트 경제 계약 테스트: 3 passed (충전 멱등성, 카드팩 사용권 환불, 보상 지급/환불)
- 상점 API/모델 테스트: 4 passed
- Alembic 전체 마이그레이션 테스트: 19 passed
- 프론트 lint: 오류 없음 (기존 경고 3건)
- 프론트 production build: 성공

남은 운영 전제는 PG 도입 전까지 관리자 포인트 조정이 충전의 유일한 발행 경로라는 점이다. 실제 금액 결제는 사업자·PG 준비 후 별도 결제 승인/취소와 대사 작업으로 추가해야 한다. 카드팩 구매 사용권과 보상 지급은 DB 트랜잭션 안에서 생성되고, 환불은 사용 전 상태에서만 원자적으로 폐기된다.
