# Fanfolio 성능 예산

모바일 팬앱의 첫 화면은 콘텐츠가 늦게 도착해도 레이아웃이 흔들리지 않고, 다음 화면으로 이동하면 이전 화면의 로딩 상태를 재사용하지 않는 것을 기준으로 한다.

## 기준

- 초기 JavaScript 청크: gzip 180KB 이하를 목표로 한다.
- 초기 CSS: gzip 90KB 이하를 목표로 한다.
- 첫 화면의 대표 이미지: `loading="eager"`, `decoding="async"`; 목록과 상세 외 이미지는 `loading="lazy"`를 사용한다.
- 모든 카드·배너 이미지는 고정 비율 상자를 먼저 렌더링하고, 실패 시 동일 크기의 시각 fallback을 표시한다.
- QR 디코더와 보호 미디어 재생기는 사용자가 해당 기능을 열 때만 동적으로 불러온다.
- 로딩 스켈레톤은 실제 요청이 완료될 때까지 유지하고, 임시 더미 콘텐츠를 실제 콘텐츠처럼 교차 표시하지 않는다.

## 검증

프런트 빌드에서 청크 크기와 경고를 확인하고, 320/390/430px에서 홈 → 탐색 → 상세 → 뒤로가기 전환을 확인한다. 이미지 요청 실패와 느린 API 응답에서도 레이아웃 이동, 빈 배너 오인, 이전 화면 스켈레톤 잔존이 없어야 한다.
